# Metadata wire probe

Reproduce the carrier decisions in [the wire contract](../../Docs/MetadataWireContract.md).
This is development tooling; the Swift library has no Python/JavaScript runtime
dependencies. Images are tiny, synthetic neutral fixtures generated by tests,
with invented resource IDs/hashes. No private reference corpus is used.

Use an installed full Xcode toolchain if Command Line Tools cannot load Testing.
The recorded run used `DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer`;
set that environment variable to your installed Xcode path if needed.

From the Musubi repository root:

```sh
probe_dir="$(mktemp -d)"
MUSUBI_WIRE_PROBE_DIR="$probe_dir" swift test --filter MetadataWireProbeTests
npm ci --prefix Tools/MetadataWireProbe --ignore-scripts --no-audit --no-fund
uv run Tools/MetadataWireProbe/a1111.py "$probe_dir"
node Tools/MetadataWireProbe/civitai.mjs "$probe_dir"
```

The Swift tests check native XMP in PNG/JPEG/HEIC, correct PNG and JPEG
compatibility carriers, a long native value, JPEG length boundaries, and the
legacy ImageIO-to-library route. Optional export writes ten fixture families
and expected text/native JSON. The eight fixtures that describe Mochi output
come from `MochiNativeCodec` and `A1111ParametersEncoder`, and include each
sampler and schedule label Mochi Diffusion writes. The `two-fields`
and `markers` limitation probes are hand-written, because the encoder refuses
to produce them. It also writes `unicode-imageio.jpeg` as a
control using ImageIO's normal UserComment API. PNG fixtures are written by
`PNGMetadataWriter` and the others by ImageIO; the JPEG probe builds a minimal
Exif segment only for its own newly generated images. These helpers are not general image editors.

Each fixture's `.expected.json` holds its exact carrier text and what each
reader must parse: `a1111` maps a key of A1111's parsed parameters to its
string, and `civitai` maps a dot-separated path into the Civitai reader's result,
such as `raw.steps`, to its value. `null` means the key is absent. Each external
oracle reads every fixture's PNG and JPEG file that exists, checks these values,
and writes a JSON result report into the fixture directory. Musubi's fixtures
assert the expected format limitations too:

- Hosted images without Steps are not recognized by the Civitai reader.
- A1111 treats a two-field details line as prompt text.
- Section markers inside prompts can change interpreted prompts/settings.
- Resource hashes/IDs/weights can be extracted; no real resource is looked up.

The control reports whether ImageIO preserved Unicode on this OS; it does not
require future OS versions to retain the observed corruption. Swift's
`legacy-results.json` similarly records direct inspection versus the working
ImageIO bridge without treating a current standalone-parser gap as a requirement.

The A1111 oracle downloads two files from a fixed commit and verifies their
SHA-256 before execution. It selects the unchanged upstream image-reader,
parameter-parser, unquoting and size-helper functions through Python's AST.
WebUI style extraction, emphasis analysis and historical version migration are
disabled; it neither installs nor starts WebUI. The scope is carrier and common
field parsing, not reproduction of all UI defaults. An upstream Python
SyntaxWarning may be printed on newer Python versions.

The Civitai oracle runs the published package with its Civitai plugin enabled,
including full container reading and schema validation. `package-lock.json`
pins package integrity and transitive versions. It performs no network lookups.
Neither oracle exercises the deployed Civitai upload UI.

After the initial source/dependency download, reruns can use the existing local
cache and fixture directory. Keep generated bytes, result reports, downloaded
source and node_modules out of source control. Read the reports alongside the
contract before changing expectations; do not blindly accept parser drift.
